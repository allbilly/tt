# Official ttsim trace patch

`ttsim-v1.10.1-readonly-elw-trace.patch` applies to Tenstorrent `ttsim` revision `3d82cd1b8e3c3d8fa69abb8ac3835c4713e4e52a` (`v1.10.1`). It modifies only upstream Apache-2.0-licensed `src/tensix.cpp` and `src/libttsim.cpp`. It adds compile-time-filtered ELW issue/state diagnostics, a callback result record for every Tensix opcode on tile ID 0 / pipe 0, and an event when one of the `MOP`, `NOP`, `MOP_CFG`, or `REPLAY` controls passes through the TRISC stream expander. ELW tracing defaults to ADD, MUL, and SUB (bits 0, 1, and 2). The generic callback record distinguishes a completed instruction from a stalled retry and preserves its raw word/opcode. Stream-control events distinguish `expanded`, `consumed`, `configured`, `load_started`, and `replayed`. The patch does not change model state transitions, checks, arithmetic, or scheduling. Trace records go to `stderr`; the simulator reads no trace-related runtime environment variables and opens no trace file.

`tools/build_trace.sh` verifies the base revision, applies or verifies the exact patch, checks that no other source files are modified, then builds only `src/_out/release_bh/libttsim.so`. `tools/compare.py` captures the instrumented child's `stderr` into `process.stderr.log` and extracts structured events into `ttsim_trace.jsonl`; it discovers the standard build path automatically, so the user's only required runtime setting remains `TTSIM_LIB`.
